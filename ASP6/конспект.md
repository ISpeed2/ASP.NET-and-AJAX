# Загрузка и скачивание файлов в ASP.NET Core MVC

## 1. Передача файлов на сервер

Файл отправляется на сервер HTTP-запросом с типом содержимого
`multipart/form-data`. В ASP.NET Core MVC отдельная часть формы связывается с
объектом `IFormFile`.

```csharp
public class FileUploadRequest
{
    [Required]
    public IFormFile? File { get; init; }

    [StringLength(500)]
    public string? Description { get; init; }
}
```

Контроллер получает модель из формы с помощью `[FromForm]`:

```csharp
[HttpPost]
public async Task<IActionResult> Upload(
    [FromForm] FileUploadRequest request,
    CancellationToken cancellationToken)
{
    var file = request.File;
    if (file is null || file.Length == 0)
        return BadRequest();

    await using var stream = file.OpenReadStream();
    // Проверка и сохранение файла
}
```

`IFormFile.FileName` и `IFormFile.ContentType` приходят от клиента, поэтому им
нельзя безоговорочно доверять.

## 2. Ограничение размера запроса

Размер файла необходимо ограничивать до начала его обработки. В проекте лимит
равен 10 МБ и проверяется на нескольких уровнях:

```csharp
[RequestSizeLimit(FileValidationService.MaxSizeBytes)]
[RequestFormLimits(MultipartBodyLengthLimit = FileValidationService.MaxSizeBytes)]
```

Общий лимит Kestrel также задаётся при запуске приложения:

```csharp
builder.WebHost.ConfigureKestrel(options =>
{
    options.Limits.MaxRequestBodySize = FileValidationService.MaxSizeBytes;
});
```

Ограничение защищает сервер от загрузки слишком больших файлов и лишнего расхода
памяти, диска и сетевого трафика. Дополнительно размер проверяется внутри сервиса
валидации, поскольку значение `IFormFile.Length` является частью входных данных.

## 3. Проверка типа файла

Проверки только расширения недостаточно: вредоносный файл можно переименовать,
например, из `.exe` в `.jpg`. Безопасная обработка включает несколько шагов:

1. Из имени извлекается только расширение через `Path.GetExtension`.
2. Расширение сравнивается с белым списком разрешённых типов.
3. Начальные байты файла сравниваются с известной сигнатурой формата.
4. После проверки позиция потока возвращается в начало.

```csharp
var header = new byte[8];
var read = await stream.ReadAsync(header.AsMemory(), cancellationToken);
stream.Position = 0;

var isPng = read >= 4 &&
    header.AsSpan(0, 4).SequenceEqual(
        new byte[] { 0x89, 0x50, 0x4E, 0x47 });
```

Заголовок `Content-Type` тоже задаётся клиентом. Его можно использовать как
подсказку, но не как единственное доказательство реального формата.

Проверка magic bytes уменьшает риск подмены типа, но не заменяет антивирусную
проверку и глубокий разбор сложных форматов. В производственном приложении файл
можно сначала помещать в карантин, сканировать и только после этого разрешать
скачивание.

## 4. Безопасное имя и место хранения

Имя загруженного файла нельзя напрямую использовать как путь. Строка может
содержать `../`, абсолютный путь или специальные символы. Это создаёт угрозу
path traversal и позволяет попытаться перезаписать произвольный файл сервера.

В проекте сервер генерирует собственный идентификатор:

```csharp
var id = Guid.NewGuid().ToString("N");
var safeOriginalName = Path.GetFileName(originalName);
```

Физическое имя состоит из GUID и проверенного расширения. Полный путь строится
через `Path.GetFullPath`, после чего проверяется, что он остался внутри каталога
хранилища.

Пользовательские файлы сохраняются в `App_Data/uploads`, а не в `wwwroot`.
Поэтому веб-сервер не раздаёт их автоматически как статические файлы. Получить
файл можно только через контроллер, где выполняются аутентификация и авторизация.

## 5. Потоковое сохранение

Файл не следует полностью загружать в массив байтов без необходимости. Потоковое
копирование уменьшает расход памяти:

```csharp
await using var output = new FileStream(
    path,
    FileMode.CreateNew,
    FileAccess.Write,
    FileShare.None,
    bufferSize: 81920,
    useAsync: true);

await input.CopyToAsync(output, cancellationToken);
```

`FileMode.CreateNew` не перезаписывает существующий файл. `CancellationToken`
позволяет прекратить операцию, если клиент отключился или запрос был отменён.

## 6. Скачивание файла

Клиент передаёт серверный ID, а сервис находит соответствующий файл в закрытом
хранилище и открывает поток только для чтения.

```csharp
[HttpGet("{id}")]
public async Task<IActionResult> Download(
    string id,
    CancellationToken cancellationToken)
{
    var result = await storage.OpenAsync(id, cancellationToken);
    if (result is null)
        return NotFound();

    var (stream, meta) = result.Value;
    return File(
        stream,
        meta.ContentType,
        meta.OriginalName,
        enableRangeProcessing: true);
}
```

Ответ содержит исходное безопасно обработанное имя, MIME-тип и заголовок
`Content-Disposition: attachment`. Браузер предлагает сохранить файл вместо его
автоматического исполнения на странице.

`enableRangeProcessing` разрешает диапазонные запросы. Клиент может продолжить
прерванное скачивание или запросить только часть большого файла.

## 7. Аутентификация и авторизация

В учебном проекте API защищён ключом из заголовка:

```http
X-Api-Key: demo-secret-key-12345
```

После проверки ключа обработчик создаёт пользователя с разрешениями
`Files.Read` и `Files.Write`. Для методов применяются отдельные политики:

```csharp
[Authorize(Policy = Policies.WriteFiles)] // загрузка
[Authorize(Policy = Policies.ReadFiles)]  // скачивание
```

Разделение разрешений следует принципу наименьших привилегий: клиенту нужно
выдавать только те возможности, которые действительно необходимы.

API-ключ нельзя хранить в исходном коде производственного приложения. Его
следует передавать через переменные окружения, Secret Manager или внешнее
хранилище секретов. Для полноценной системы пользователей обычно применяют
cookie-аутентификацию или JWT/OAuth 2.0.

## 8. Клиентская отправка и скачивание

Для отправки используется `FormData`. Прогресс загрузки удобно получать через
`XMLHttpRequest.upload.onprogress`:

```javascript
const form = new FormData();
form.append('file', file, file.name);

const xhr = new XMLHttpRequest();
xhr.open('POST', '/api/files');
xhr.upload.onprogress = event => {
    if (event.lengthComputable) {
        const percent = Math.round(event.loaded / event.total * 100);
    }
};
xhr.send(form);
```

При скачивании JavaScript получает ответ как `Blob`, создаёт временный URL и
запускает сохранение через ссылку с атрибутом `download`. После этого временный
URL освобождается вызовом `URL.revokeObjectURL`.

## 9. Обработка ошибок и журналирование

API должен возвращать понятный код ошибки, сообщение и correlation ID:

```json
{
  "code": "validation_failed",
  "message": "Расширение '.exe' не разрешено",
  "correlationId": "20c7e969-7009-4c45-b5fd-b4af2631588d"
}
```

Correlation ID передаётся между компонентами и записывается в журнал. Это
позволяет найти все записи, относящиеся к одному запросу, не раскрывая клиенту
внутренние детали исключения.

В логах не следует сохранять содержимое файла, API-ключ и другие секретные или
персональные данные.

## 10. Основные угрозы

Для анализа безопасности можно использовать модель STRIDE:

| Категория | Пример для файлового API | Защитная мера |
| --- | --- | --- |
| Spoofing | Загрузка от имени другого клиента | Аутентификация |
| Tampering | Подмена типа или содержимого | Проверка расширения и сигнатуры |
| Repudiation | Отказ от факта загрузки | Журналирование и correlation ID |
| Information Disclosure | Скачивание чужого файла | Авторизация и закрытое хранилище |
| Denial of Service | Огромные или многочисленные файлы | Лимиты размера и rate limiting |
| Elevation of Privilege | Выполнение загруженного файла | Хранение вне `wwwroot`, attachment |

## Итог

- Загруженный файл является недоверенными входными данными.
- Размер, расширение и фактическое содержимое нужно проверять на сервере.
- Для хранения следует генерировать собственное имя и исключать path traversal.
- Пользовательские файлы безопаснее держать вне каталога статических ресурсов.
- Загрузка и скачивание должны проходить через аутентификацию и отдельные
  политики авторизации.
- Потоковая обработка снижает расход памяти и поддерживает отмену запроса.
- Структурированные ошибки и correlation ID упрощают диагностику.
